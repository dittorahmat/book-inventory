# Aturan Database & Cloudflare D1

Dokumen ini memuat aturan kanonik dan mandat anti-kambuh untuk skema database, disiplin penulisan batch Cloudflare D1, integritas relasional, serta pencegahan drift skema remote.

---

## Mandat Anti-Kambuh

### §0.10. Integritas Skema & Anti-String-Packing
Data terstruktur domain (seperti nomor WA manual, tautan dokumen finance) wajib dialokasikan di kolom skema resmi atau objek terstruktur, dilarang dipadatkan (packed) ke dalam string catatan bebas (`notes`) dengan tag parsing darurat (`[WA: ...]`). Ditegakkan mekanis oleh `check:string-packing`.

### §0.11. Disiplin Validasi Bukti Dokumen
Input bukti dokumen (seperti Surat Jalan atau surat rekomendasi) wajib menyediakan alur upload file (data-URL/blob/storage) dan penambahan validasi wajib tidak boleh merusak pemanggil lama tanpa migrasi lengkap di diff yang sama.

### §0.19. Disiplin Batching D1 pada Seeder
Seluruh penambahan data di seeder (`seed.ts` maupun `seed-demo/*.ts`) wajib mematuhi batas chunking D1 (maksimal 10 baris per statement `INSERT ... VALUES` via `chunkRows` atau `runWriteBatch`), dilarang melakukan perulangan insert satu per satu (`insert().values({ ... })` tunggal).

### §0.26. Integritas Penamaan Entitas & Anti-Residual Identifier
Saat melakukan perubahan identitas nama data demo/domain (seperti nama siswa, kode akun, atau nomor referensi), lakukan penyelarasan menyeluruh hingga ke ID slug seeded (`id`, `orderId`, `receiptId`) untuk mencegah bau kode leaky identifier / mismatch kognitif antara nama tampilan dan kunci relasi database. Ditegakkan mekanis oleh gate `check:seed-integrity`.

### §0.27. Disiplin Batch Updates Mutasi Masal D1
Seluruh operasi pembaruan masal multi-baris (seperti kenaikan kelas murid `batchPromoteStudents`, mutasi status katalog, atau pengalihan lokasi) wajib mengelompokkan ID target ke dalam chunk aman D1 (`chunkRows` dari `src/server/lib/d1-write.ts`) dan menggunakan predikat set `inArray(table.id, chunk)` atau `db.batch()`, dilarang mengeksekusi perulangan `database.update().where(eq(id))` satu per satu.

### §0.30. Disiplin Sinkronisasi Skema Remote D1 & Anti-Drift
Setiap penambahan atau modifikasi migrasi SQL di folder `drizzle/*.sql` wajib diverifikasi kelengkapannya ke remote Cloudflare D1 (`bun run check:d1-drift` dan `wrangler d1 execute book-inventory-db --remote`) sebelum menguji endpoint produksi atau membuat PR. Skrip `check:fast` secara otomatis memicu alarm drift bila ada berkas migrasi yang berubah, dan runner `bun run deploy` otomatis mengeksekusi gate `check:d1-drift` sebelum deploy worker. Dilarang membiarkan perbedaan kolom antara schema kode TypeScript dan SQLite remote.

### §0.34. Disiplin Whitelist Single-Writer Gate & Integritas Seeder
Pengecualian pada gate `check:single-writer` hanya diizinkan untuk baseline seeder utama (`src/server/seed.ts`) atau file seeder demo spesifik yang tercantum secara eksplisit (*exact whitelist*, misal `seed-demo/orders.ts`); dilarang menggunakan wildcard atau prefix glob/directory sweeping (`startsWith("src/server/seed-demo/")`) yang dapat melemahkan penegakan arsitektur single-writer secara tidak sengaja di seluruh seeder baru.

### §0.54. Disiplin Navigasi Skema Relasi & Factory Test Fixtures
1. **Pemisahan Scope Skema Global vs Cabang**: entitas katalog terpusat (`books`, `book_packages`, `uniform_variants`, `uniform_packages`) dilarang diasumsikan memiliki kolom `school_id`; konsultasikan `src/db/SCHEMA_OVERVIEW.md` sebelum merakit query atau fixtures baru.
2. **Penggunaan Factory Test Fixtures Kanonik**: penyusunan data awal pengujian (test fixtures) wajib memanfaatkan helper kanonik di `src/server/lib/test-fixtures.ts` (`createTestSchool`, `createTestStudent`, `createTestBookOrder`, `createTestPackage`, `createTestBook`) alih-alih merakit baris mentah `insert().values({...})` yang rentan terhadap kegagalan kolom `NOT NULL` SQLite.
3. **Kelengkapan Antarmuka Pengguna pada Fitur Intake**: penambahan alur intake atau percabangan submit baru di backend tidak boleh berhenti di layer API/state belaka; implementasi dinyatakan selesai (*Definition of Done*) hanya jika telah menyediakan komponen antarmuka pengguna visual (modal/dialog/form) yang teruji secara interaktif.

### §0.55. Disiplin Layanan Integrasi Cloud & In-Memory Stream (Cloudflare Workers)
1. **Seam Layanan Drive Tunggal**: pembacaan berkas atau resource Google Drive / Google Sheets (`/api/books/parse-drive-url` dan `/api/students/parse-drive-url`) wajib didelegasikan ke seam terpusat `drive-service.ts` (`src/server/services/drive-service.ts`), dilarang menduplikasi logika proxy parsing URL Google Drive/Sheets di handler router.
2. **Kompatibilitas Cloudflare Workers (No-Filesystem)**: integrasi pihak ketiga pada server backend wajib murni berbasis Web Standard API (`fetch`, `Response.text()`, `Response.arrayBuffer()`, memory stream) tanpa ketergantungan pada modul sistem operasi atau disk filesystem Node (`fs`, `tmp`, `curl`). Seluruh manipulasi berkas eksternal di runtime harus in-memory stream agar 100% kompatibel saat dideploy ke Cloudflare Workers (`worker.dev`).
3. **Penegakan Sinkronisasi Harga Paket Otomatis**: setiap import katalog buku yang mengaktifkan auto-bundling paket (`autoCreatePackages: true`) wajib mengeksekusi seam kanonik `recalcPackagePrice(database, packageId)` (§0.28) seketika BOM terbentuk agar total harga paket buku selalu tersinkronisasi all-in di database.
4. **Kanonikalisasi Penerbit Al-Wildan & Guard Batch Selesai**: inferensi cerdas katalog buku wajib memetakan varian Al-Wildan secara kanonik ke `"Al-Wildan Press"` (publisher consistency); batch folder runner (`DriveFolderBatchRunner`) dilarang memicu `onComplete()` jika seluruh berkas gagal atau menghasilkan 0 baris valid guna mencegah penyelesaian prematur modal intake.
5. **Seam Hook Koordinasi Drive Intake & Penegakan Mekanis Test-DOM**: koordinasi state dan pengambilan berkas Google Drive di modal frontend wajib memusat ke custom hook kanonik `useDriveFolderIntake` (`src/components/ui/useDriveFolderIntake.ts`), dilarang menduplikasi pasangan state `sheetsUrl`/`folderFiles`/`isParsingDrive` di masing-masing modal. Seluruh pengujian komponen antarmuka React (`*.test.tsx`) yang merender DOM wajib memakai shim `test-dom` dan dynamic import `@testing-library/react`, ditegakkan secara mekanis di pre-commit dan CI oleh gate `check:test-dom`.
6. **Resolusi Subfolder Google Drive Tanpa False-Positive**: ekstraksi berkas folder Google Drive di `src/lib/sheets.ts` wajib memisahkan subfolder dengan spreadsheet berdasarkan atribut penanda kontainer folder Google Drive (`aria-label`), dilarang memakai pencocokan substring nama berkas secara longgar (`name.includes("folder")`) yang dapat menimbulkan *false positive* pada spreadsheet dengan judul sah (misal `"Folder Rekap Buku.xlsx"`), dan konsumen `useDriveFolderIntake` wajib memfilter item hanya untuk berkas berjenis spreadsheet (`type === "spreadsheet"`).
7. **Resiliensi Throttling Drive & Anti-Collision Fallback ISBN**: fetcher Google Drive wajib menerapkan retry berjenjang (exponential backoff) saat terkena 503/429 throttling; batch processing folder wajib menyertakan jeda pacing (~800ms) antar berkas; generator kode buku internal fallback (`slugifyBookCode`) wajib menyertakan hash deterministik untuk mencegah benturan `UNIQUE constraint books.isbn` pada judul-judul panjang; dan deduplikasi chunk import wajib divalidasi berbasis kanonik ISBN `resolveBookIsbn`. Spreadsheet rekap non-katalog buku wajib direspons graceful (warning informatif) tanpa melempar unhandled 500.

### §0.57. Disiplin Migrasi D1 Non-Destruktif & Anti-Recreation Drop
1. **Dilarang Table Recreation Drop pada D1**: Drizzle Kit secara default membuat migrasi recreation (`CREATE TABLE __new_*`, copy data, `DROP TABLE ...`) pada SQLite ketika terjadi modifikasi kolom/enum. Dilarang keras menerapkan file migrasi `DROP TABLE` pada Cloudflare D1 remote yang berelasi foreign key atau data operasional aktif tanpa rencana expand-contract dua PR (§1.3).
2. **Kanonikalisasi ALTER TABLE Aman**: Penambahan kolom baru wajib disederhanakan ke pernyataan SQL `ALTER TABLE <table> ADD COLUMN <col> <type>;` yang idempoten dan aman dieksekusi langsung tanpa menghapus data tabel induk/anak.

### §0.64. Disiplin Penyelarasan Pengadaan Katalog & Mutasi Massal Aman-D1
1. **Integritas Penyelarasan Supplier**: pemetaan katalog buku ke supplier wajib memprioritaskan distributor spesifik per mata pelajaran/jenjang (misal Mentari untuk Cambridge Secondary Sains, CNL untuk Scholastic & Primary, Pelangi untuk PAUD/TK) guna mencegah tabrakan aturan (*rule collision*) akibat kesamaan kata kunci penerbit.
2. **Disiplin Batch Updates Mutasi Katalog**: pembaruan massal ISBN atau harga beli (`syncBookCatalogPricingAndIsbn`) wajib mengelompokkan query ke dalam potongan batch aman (`chunkRows` + `runWriteBatch`), dilarang mengeksekusi loop `update()` unbatched satu per satu pada D1.
3. **Pembersihan Entitas Master Yatim yang Atomik**: pembersihan entitas master duplikat/yatim (`cleanupOrphanDuplicateBooks`) wajib memverifikasi ketiadaan seluruh relasi operasional (stok, order siswa, PO, shipment internal/transfer) dan dieksekusi dalam satu transaksi atomik batch (`runWriteBatch`) bersama tabel anak terkait.
4. **Kalkulasi Otomatis Harga Paket Baru**: penambahan master paket kurikulum baru (seperti jenjang prasekolah PG/K1/K2) wajib mengeksekusi seam kanonik `recalcPackagePrice(targetDb, pkg.id)` seketika item BOM terdaftar agar harga paket selalu mencerminkan akumulasi harga jual komponen riil dan bukan nilai hardcoded.
5. **Seeding Saldo Stok Awal & Pencegahan Raw SQL Generator**: seeding saldo awal atau rekonsiliasi stok ke database (lokal maupun D1 remote) dilarang merakit raw SQL `INSERT INTO book_stocks` secara ad-hoc di skrip bebas; mutasi saldo dan jejak audit wajib didelegasikan ke seam kanonik `seedInitialBookStock` yang membungkus `moveInventoryStock` (§0.62). Generator script utilitas data wajib menggunakan path relatif proyek yang portabel (dengan fallback argumen CLI `process.argv[2]`), dan berkas SQL hasil generasi wajib disimpan di `data/sql/`, dilarang diletakkan di `drizzle/` yang dapat merusak integritas `check:clean-artifacts` dan urutan migrasi.

## Disiplin Tulis Cloudflare D1 & Workers (Detail Teknis Eks-§10)

Latar dan bukti: `CODING_STANDARDS.md` §6. Aturan yang mengikat:

1. Satu statement `INSERT ... VALUES` maksimal **10 baris**, dieksekusi sekuensial (chunked).
2. `Promise.all` **dilarang** untuk operasi tulis; gunakan eksekusi sekuensial atau `db.batch()`.
3. Alur mutasi induk + anak wajib atomik (`db.batch()` di D1, fallback sekuensial di bun-sqlite) atau idempoten dengan validasi pra-tulis yang mengembalikan 400.
4. Constraint SQLite (`UNIQUE`/`FOREIGN KEY`) wajib dipetakan ke status HTTP 4xx lewat `d1WriteErrorStatus()` (`src/server/lib/d1-write.ts`); kegagalan infra (`D1_ERROR`) wajib dilempar ulang agar menjadi 500 + ref, bukan 400 palsu.
5. Endpoint tulis bervolume wajib diuji ≥30 baris sekaligus di `src/server/routes/*.test.ts`.
6. Eksekusi SQL remote manual atau seeder masal ke Cloudflare D1 wajib memakai runner kanonik `bun scripts/d1-remote-batch.ts --file="..."` atau `bun scripts/d1-remote.ts --command="..."`, membatasi ukuran pernyataan di bawah batas limit D1 code 7500 (maksimal chunk 10 baris per query, hindari compound SELECT berlebih), selalu menyediakan timestamp audit lengkap (`created_at` dan `updated_at`), dan menyisipkan data induk sebelum data anak ber-foreign-key (`books`/`book_packages` sebelum `book_package_items`).
7. **Disiplin Query IN-List D1 & Cold Start**: Pembacaan SQL dengan daftar dinamis `inArray(col, ids)` berpotensi melebihi batas parameter D1/SQLite (error 500 di production). Wajib memakai seam kanonik `selectInChunks(ids, (chunk) => db.select()...)` dari `src/server/lib/d1-write.ts` (chunk default `D1_INLIST_CHUNK_SIZE = 90`). Inisialisasi modul auth/worker dilarang melempar exception fatal di level top-level modul saat bundling upload (`wrangler deploy --dry-run`).
8. **Disiplin Chunking & Bound-Parameters Bulk Import D1**: Cloudflare D1 memiliki batas keras maksimal 100 parameter terikat (`?`) per statement SQL. Pada tabel bervolume kolom lebar (seperti `students` dengan 12 kolom), chunking insert wajib dibatasi maksimal **5 baris per query** ($5 \times 12 = 60 < 100$) dan dieksekusi sekuensial per chunk untuk menghindari kegagalan D1 batch timeout saat import ratusan/ribuan data. Logika import wajib idempoten (upsert berbasis unique constraint / natural key) sehingga bila terjadi kegagalan jaringan di tengah jalan, proses dapat diulang tanpa konflik duplikat.
9. **Disiplin Runner Remote D1 Batching & Node v26 GC Bug**: skrip eksekusi D1 remote (`scripts/d1-remote-batch.ts`) dilarang membiarkan file-handle terbuka saat eksekusi batch di sistem operasi Windows (`ERR_INVALID_STATE`). Saat menjalankan wrangler CLI untuk eksekusi file SQL remote (`d1 execute --file=...`), **selalu jalankan melalui runtime Bun** (`bun run wrangler ...`, `bun run db:d1:exec`, atau `bun run db:d1:batch`), **dilarang menggunakan `npx wrangler`** karena host Windows dengan Node.js v26+ memicu fatal crash `A FileHandle object was closed during garbage collection [ERR_INVALID_STATE]`. Seluruh skrip di `scripts/**` wajib mematuhi batasan tulis D1 (§10.1–§10.2) yang ditegakkan mekanis oleh `check:d1-writes`.
10. **Disiplin Integritas Master Katalog & Paket Buku (§0.66)**: Dilarang mendaftarkan item paket buku (`book_package_items`) yang merujuk ke ID buku tanpa stok fisik aktif jika ada ID buku duplikat lain yang memegang saldo riil. Seluruh item paket buku wajib divalidasi tidak orphan via gate `check:catalog-integrity`. Seeder paket wajib memakai ID buku kanonik yang telah terisi saldo transfer fisik gudang.
11. **Kamus Identitas Sekolah Kanonik (§0.65)**: Seluruh referensi kode dan ID sekolah di server backend, script migrasi, dan seeder wajib mengimpor konstanta kanonik `SCHOOL_IDS` dan `SCHOOL_CODES` (`src/server/lib/school-constants.ts`), dilarang menebak atau menggunakan string literal sembarangan (misal `"school-aw-1"` vs ID resmi `"school-alw-1"`).
12. **Disiplin Sinkronisasi Skema Drizzle vs Data Katalog D1 (§0.73)**: Sinkronisasi skema struktur tabel D1 dikelola via migrasi formal Drizzle (`bun run db:generate` lalu `bun run db:d1:migrate`). Penyelarasan isi data/katalog operasional (seperti master varian seragam, matriks ukuran `uniform_sizes`, atau BOM paket) dilarang menggunakan driver SQLite lokal langsung (`bun:sqlite`), melainkan wajib dirancang D1-portable: menghasilkan skrip SQL aman di `data/sql/` atau dieksekusi melalui runner D1 (`bun run db:d1:exec` / `bun run db:d1:batch`) dengan subquery berbasis natural key / natural selection ke tabel target guna mencegah pelanggaran foreign key antara database lokal dan remote.
